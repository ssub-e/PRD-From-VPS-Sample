# PRD v1.0 리뷰 결과 및 보완 계획 (Action Plan)

## 1. 개요
* 대상 문서: `PRD-v1.0.md`
* 목적: 누락된 구조 파악 및 표준 PRD 형식에 맞춘 보강 계획 수립
* 핵심 결론: **VPS 문서, MVP Feature Map, 경쟁사 분석 등 이전 단계 산출물에서 누락된 데이터를 재추출하여 문서 보강 필수**

## 2. 문서별 상세 피드백 및 수정 계획
1. **[삭제] 2-3. AOS-DOS 사분면 요약**
   * 사유: PRD 표준 구조상 불필요하게 분리된 챕터이므로 삭제. 모델 분석 내용은 '1.1 문제 정의(Pain)' 등 서문에 녹여 서술.
2. **[유지] AC (Failure Path) 예외 처리 스펙**
   * 사유: Acceptance Criteria 작성 시 예외 상황(장애, 타임아웃 등) 기준을 잡아두는 좋은 의도.
3. **[보완] 기능 요구사항 MoSCoW 우선순위 스펙**
   * 현재 상태: Must, Won't 만 존재
   * 보완 계획: VPS 및 기능 목록을 점검하여 Should Have, Could Have 항목 재추출 후 적정 개수 이상 반영.
4. **[수정] 4-3. 차별 및 포지셔닝 전략**
   * 사유: '4사분면'이라는 내용이 삭제되므로 이해할 수 없는 문맥 제거.
   * 보완 계획: Niche 기반 특화 전략이라는 텍스트 중심으로 전면 수정 및 포지셔닝 맵 이미지 재활용 고려.
5. **[삭제] 10. 비즈니스 모델 챕터**
   * 사유: 상품 과금 티어(Tier) 등 사업화 기획 내용은 PRD 본연이 요구하는 기술/제품 요구사항 정의와 맞지 않으므로 GTM/제품사업계획서로 이관 후 삭제.

## 3. 구조적 측면 추가 권장 항목 (표준 템플릿 기준)
표준 PRD(sample-prd-CHY.md 등)를 참고하여 다음 섹션을 새롭게 추가해야 합니다.

1. **제품 원칙 및 의사결정 게이트 (Decision Gate)**: 팀 내 기능 반려/결정 기준 추가 (1장에)
2. **경쟁 대안 대비 수치 목표**: 제품이 경쟁 솔루션보다 낫다고 증명할 명확한 벤치마크 숫자 (4장에)
3. **In Scope / Out of Scope**: 개발/기획 범위 방어막 (7장에)
4. **롤아웃(배포) 계획**: 베타 버전부터 일반 출시까지의 단계별 계획 설정 (8장에)

## 4. 향후 플랜 (Next Steps)
1. 이전 단계의 **VPS(Value Proposition Sheet) 및 기능 맵(Feature Map) 분석 문서 추출.**
2. MoSCoW의 S, C 요소, In/Out Scope, 경쟁 대안 정량 지표 데이터 스크랩.
3. 확보된 자료를 토대로 PRD 본문 전면 수정 및 구조 개편(v1.1 작성).
